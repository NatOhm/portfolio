## Phase 1 — archive covers that fit the card (done)

**Problem.** Some cards showed a sliced band of a poster. `ArchiveCard.tsx`
renders the cover in an `aspect-[5/4]` frame with `object-cover`, so any cover
taller than 5:4 loses its top and bottom. Six covers were tall artwork:

| collection | real cover | size |
| --- | --- | --- |
| `tk-reels` | reel frame | 1080×1920 |
| `manipulation` | personal artwork | 1000×1500 |
| `infographic` | info board | 1600×2558 |
| `tine-2026` | graduation shoot | 1367×2048 |
| `breezee-menu` | menu page | 1600×2263 |
| `pattaya-posts` | post graphic | 1080×1350 |

**Fix.** Each now uses a derived 1600×1280 "cover plate": the whole piece fitted
and centred (never cropped) on a mat — its own artwork blown up, blurred past
recognition, scaled to a constant darkness and vignetted, with a 1px hairline
separating piece from mat. The mat is dimmed by a measured gain, not a fixed
multiplier: a near-white board would otherwise keep a washed-out mat next to a
dark render's near-black one. `Silly Fool – Deep Cut` was re-plated the same way
so the set shares one mount. Generated by `scripts/lib/cover-plate.mjs`:

```bash
node scripts/lib/cover-plate.mjs <source-image> public/images/covers/<id>.jpg
```

Output goes to `public/images/covers/<id>.jpg`, 1600×1280, and
`src/lib/archive-covers.ts` points at it with `src` / `width` / `height` / `alt`.
Next caches optimised images by URL, so after regenerating a plate delete
`.next/cache/images` (or the old crop keeps being served).
`CoverChoice` already had that shape from the BlueVenture and Silly Fool covers,
so nothing in `src/lib/archive.ts` changed. The file needs `ffmpeg` on PATH.

**Also in this phase.** `sci-fi-environment`'s cover was a 426×426 poster, soft
at card size, so it now uses a 1280×720 piece from the same set (the synthwave
city with the eclipsed sun). `anim-hoodie-process` is 1600×1132 — the 5:4 crop
only trims a little and keeps all three characters, so it was left alone.

**Still soft.** `social-3d` cannot be sharpened: every item in that collection
is a 206×206 Instagram thumbnail. It needs the original renders from the source
library before it can be fixed properly.

## Phase 2 — Thai type (done)

**Problem.** `/th` rendered Thai through the OS fallback (Leelawadee UI /
Thonburi) while inheriting the Latin scale: display leading 0.92, tracking
−0.035em. Thai stacks vowels and tone marks above and below the baseline, so
headlines collided and marks clipped.

**Faces.** Chosen by structural match, not by mood:

- Display → **Bai Jamjuree 600**, the Thai squarish grotesk that matches
  Bricolage Grotesque's low-contrast, flat-terminal, tight skeleton.
- Text → **Anuphan Variable**, loopless, built to sit beside Inter.
- `@fontsource/bai-jamjuree/thai-600.css` and `@fontsource-variable/anuphan`
  are imported in `src/app/layout.tsx`. Only Thai subsets ship: 12 KB + 20 KB
  of woff2. Both OFL.

**How they attach.** Not by replacing tokens, but by extending the stacks:
`--font-display` ends with Bai Jamjuree, `--font-body` and `--font-meta` end
with Anuphan Variable. Latin glyphs still resolve to Bricolage / Inter / Space
Mono first, so `Motion Graphics` inside a Thai sentence keeps the site's face
and only Thai glyphs fall through.

**Metrics.** `.thai-type` (in `src/app/globals.css`) overrides only the Thai
scope:

| token | Latin | Thai |
| --- | --- | --- |
| `--text-display-xl` | lh 0.92, ls −0.035em | lh 1.24, ls −0.005em |
| `--text-display-l` | lh 0.98, ls −0.03em | lh 1.26, ls −0.005em |
| `--text-title` | lh 1.15, ls −0.02em | lh 1.4, ls 0 |
| `--text-3xl` (md section heads) | lh 1.2 | lh 1.34 |
| `--text-lede` | lh 1.5 | lh 1.75 |
| `--text-meta` | lh 1.2, ls 0.12em | lh 1.45, ls 0.04em |

Wide tracking between Thai glyphs reads as broken syllables, hence the drop;
meta and section heads need air above them rather than spacing.

**Verified** in the running build: both fonts load; canvas measurement confirms
Thai text resolves to Bai Jamjuree and not a system face; the overrides compute
as 1.24 / 1.26 / 1.45 / 0.04em; no horizontal overflow on `/th`. The leading was
tightened once already — a marked syllable reaches ~1.2em of ink ascent in Bai
Jamjuree, so anything under ~1.2 collides on multi-line headlines.

## Running it

```bash
npm run dev                  # next dev on 3000
npx tsc --noEmit && npx eslint . --max-warnings=0
npm run verify:archive       # every renderable file appears exactly once
npm run build && npx next start -p 3125
```

Local preview for screenshots and review has been a production server on port
3125: `nohup npx next start -p 3125 > .preview.log 2>&1 &`. It serves a snapshot
of `public/` taken at boot, so **restart it after adding files to `public/`** —
fresh covers otherwise 404 until then.

## Gotchas

- `src/lib/archive.generated.json` is generated by `scripts/build-archive.mjs`.
  Never hand-edit it. Covers belong in `archive-covers.ts`; collection copy,
  order and `previewSeconds` belong in `archive-collections.ts`.
- `scripts/build-archive.mjs` builds one collection per run and merges into the
  existing JSON. `ARCHIVE_FORCE_VIDEO=1` re-encodes instead of reusing.
- The `ffmpeg` `tile` filter is broken on this machine; compose contact sheets
  with `xstack` and an explicit layout instead.
- Cover plates are derived: if a source poster changes, regenerate the plate.
- `.thai-type` currently wraps only the Thai homepage. Any new Thai page needs
  the same wrapper, or its Thai glyphs fall back to the OS face again.
